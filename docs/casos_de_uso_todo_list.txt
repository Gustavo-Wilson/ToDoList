CASOS DE USO — TO-DO LIST

UC01 — Cadastrar usuário

Ator: Usuário

Objetivo:
Permitir que uma pessoa crie uma conta para utilizar o sistema.

Pré-condição:
O usuário ainda não possui uma conta cadastrada com aquele e-mail.

Fluxo principal:
1. O usuário acessa a tela de cadastro.
2. O sistema solicita os dados necessários.
3. O usuário informa seus dados.
4. O usuário confirma o cadastro.
5. O sistema valida os dados fornecidos.
6. O sistema verifica a disponibilidade do e-mail.
7. O sistema cria a conta.
8. O sistema informa o resultado da operação.

Fluxos alternativos:
FA01 — Dados obrigatórios ausentes:
O sistema informa quais campos precisam ser preenchidos.

FA02 — Dados inválidos:
O sistema informa que os dados fornecidos são inválidos e solicita a correção.

FA03 — E-mail já utilizado:
O sistema não revela se o endereço está associado a uma conta e apresenta uma mensagem genérica orientando o usuário a verificar os dados ou utilizar o fluxo apropriado de recuperação/acesso.

Pós-condição:
Um novo usuário é persistido no banco de dados e pode utilizar o sistema.


UC02 — Autenticar usuário

Ator: Usuário

Objetivo:
Permitir que um usuário acesse sua conta de forma segura.

Pré-condição:
O usuário possui uma conta cadastrada.

Fluxo principal:
1. O usuário acessa a tela de login.
2. O sistema solicita e-mail e senha.
3. O usuário informa suas credenciais.
4. O sistema valida as credenciais.
5. O sistema autentica o usuário.
6. O sistema concede acesso às funcionalidades permitidas.

Fluxos alternativos:
FA01 — Credenciais inválidas:
O sistema informa que não foi possível realizar a autenticação sem revelar qual informação está incorreta.

FA02 — Campos obrigatórios ausentes:
O sistema informa quais campos precisam ser preenchidos.

Pós-condição:
O usuário está autenticado e pode acessar suas funcionalidades.


UC03 — Criar tarefa

Ator: Usuário

Objetivo:
Permitir que o usuário crie uma nova tarefa.

Pré-condição:
O usuário está autenticado.

Fluxo principal:
1. O usuário acessa a criação de tarefa.
2. O sistema apresenta o formulário.
3. O usuário informa os dados da tarefa.
4. O usuário confirma a criação.
5. O sistema valida os dados.
6. O sistema cria e persiste a tarefa.
7. O sistema informa que a tarefa foi criada com sucesso.

Fluxos alternativos:
FA01 — Dados inválidos:
O sistema informa os campos que precisam ser corrigidos e não cria a tarefa.

Pós-condição:
Uma nova tarefa é associada ao usuário e persistida no banco de dados.
